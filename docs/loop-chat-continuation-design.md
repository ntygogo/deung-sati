# คุยเรื่องเดิมต่อจาก Loop Trace

สถานะ: นำไปพัฒนาแล้วใน PR #9 วันที่ 18 กันยายน 2026 ตรวจร่าง คุยต่อหลังยืนยัน และลบประวัติบน preview แล้ว ดูหลักฐานและข้อจำกัดใน docs/qa/loop-continuation-and-future-self.md

## ทางเข้าที่ผู้ใช้เห็น

กดการ์ดลูป → เห็นสรุปที่บันทึก พร้อมวันที่ → เลือก “คุยเรื่องนี้ต่อ” หรือ “อ่านแชทเดิม”

“อ่านแชทเดิม” เปิดประวัติแบบอ่านอย่างเดียว ไม่สร้างข้อความหรือเปลี่ยนคะแนน ส่วน “คุยเรื่องนี้ต่อ” เปิดแชทพร้อมแถบชื่อเรื่องและวันที่ของลูป ผู้ใช้เลื่อนอ่านส่วนเก่าได้ และข้อความที่กลับมาคุยแยกด้วยวันที่ชัดเจน ไม่เริ่มถามทั้งแปดช่องซ้ำ

ถ้ายังไม่ได้พิมพ์อะไร คำเปิดอาจเป็น “ครั้งก่อนเธอเล่าว่า… หลังจากวันนั้นมีอะไรที่อยากคุยต่อไหม?” โดยอ้างเพียงประเด็นที่ผู้ใช้ยืนยันไว้และระบุว่าเป็นเรื่องครั้งก่อน ไม่สรุปว่าอารมณ์เก่ายังเป็นอยู่ตอนนี้ ไม่ถามซ้อนหากผู้ใช้เริ่มเล่ามาแล้ว

## แยกตามชนิดของบันทึก

| สิ่งที่เปิด | พฤติกรรม |
| --- | --- |
| แบบร่าง | เปิดแชทที่ผูกกับร่างเดิม คืนช่องที่มีและสถานะข้าม เริ่มจากสิ่งที่อยากคุยตอนนี้ เมื่อบันทึกใช้ร่างเดิม ไม่สร้างร่างซ้ำ |
| ลูปยืนยันแล้ว | อ่านบันทึกและแชทเดิมได้ การคุยต่อเป็นช่วงใหม่ที่เชื่อมกับลูปนั้น บันทึกที่ยืนยันแล้วและประวัติรางวัลยังคงเดิม |
| ลูปที่เขียนเอง หรือแชทต้นทางไม่มีแล้ว | เสนอ “เริ่มคุยจากลูปนี้” โดยแจ้งว่าเริ่มจากสรุปที่มี ไม่มีการสร้างบทสนทนาเก่าขึ้นมาทดแทน |

การคุยต่อหรือเปิดแชทเก่าไม่เพิ่ม XP / Shells / จำนวนลูป การทำความเข้าใจเพิ่มเติมอยู่ในบทสนทนาต่อเนื่อง หากต่อมามีเหตุการณ์ใหม่และผู้ใช้เลือกบันทึกลูปใหม่ จึงใช้กระบวนการตรวจและยืนยันปกติ ไม่คัดลอกลูปเก่าไปยืนยันซ้ำ

## จุดเริ่มต้นก่อนพัฒนาฟีเจอร์นี้

ตรวจจาก main b5b4985 ณ วันที่ออกแบบ:

- loop_traces มี source_session_id และระบบร่างมีการอ้าง conversationId แล้ว
- App เก็บ chatMessages ใน React state และส่ง sessionId แบบ default-session ขณะที่หน้าบันทึกใช้ conversationIdRef อีกตัว จึงต้องใช้ตัวระบุบทสนทนาเดียวกันตลอดทางก่อนทำปุ่มกลับมาคุย
- server/sessionStore.ts เป็น Map ในหน่วยความจำ ไม่ใช่คลังประวัติถาวรข้ามการรีสตาร์ตหรืออุปกรณ์
- ลูปบันทึกข้อมูลสรุป ไม่ได้ส่งข้อความทั้งหมดไปพร้อมการสร้างร่าง จึงไม่ควรอ้างว่าสามารถกู้แชทเก่าที่ไม่เคยถูกเก็บไว้ได้

## ขอบเขตการทำเวอร์ชันแรก

1. เก็บบทสนทนาและข้อความอย่างถาวร แยกเจ้าของบัญชี พร้อมลำดับข้อความและรหัสป้องกันบันทึกซ้ำ ใช้ conversationId เดียวในแชท ร่าง และ trace
2. API อ่าน/ต่อบทสนทนาตรวจเจ้าของจากการเข้าสู่ระบบ ไม่เชื่อ userId ที่ลูกค้าส่งเอง โหมดทดลองเก็บในเครื่องพร้อมบอกขอบเขตการกลับมาเปิด ไม่สัญญาว่าจะข้ามอุปกรณ์
3. เชื่อมลูปกับบทสนทนาต้นทาง และบทสนทนาต่อเนื่องหลายช่วง โดยไม่แก้ growth event หรือ confirmed trace เดิม
4. เมื่อกลับมาคุย ให้ AI ได้สรุปต้นทางที่แยกชัดว่าเป็นอดีต และข้อความล่าสุดที่จำเป็น ข้อความเก่าไม่ถือเป็นหลักฐานใหม่สำหรับการนับลูปหรือรางวัล
5. เพิ่มปุ่มในรายละเอียดลูป พร้อมสถานะโหลด ลองใหม่เมื่อเน็ตหลุด และทางออกกลับไปดูสรุป ปิด “อ่านแชทเดิม” เมื่อไม่มีประวัติจริง
6. การลบประวัติยังคงลบได้ ปุ่มคุยต่อไม่กู้ข้อความที่ลบไปแล้วจากสำเนาลับ หากเก็บสรุปลูปไว้ ให้แจ้งว่ามีเฉพาะสรุปนั้น

## เงื่อนไขตรวจรับ

- ปิดหน้าแล้วกลับมาเปิดลูปเดียวกัน ได้ข้อความเดิมตามลำดับและเจ้าของที่ถูกต้อง
- ร่างกลับมาแก้ต่อและบันทึกเป็นร่างเดิมได้โดยไม่ซ้ำ
- ลูปยืนยันแล้วคุยต่อได้ โดยบันทึกเดิม คะแนน และจำนวนลูปไม่เปลี่ยน
- ข้อความว่า “ตอนนี้ไม่รู้สึกแบบเดิมแล้ว” ไม่ถูกตอบด้วยการยืนยันอารมณ์เก่า
- บัญชีอื่นอ่านประวัติไม่ได้ แม้รู้รหัสลูปหรือบทสนทนา
- กดซ้ำ รีโหลด หรือส่งซ้ำหลังเน็ตหลุด ไม่ทำให้ข้อความหรือรางวัลซ้ำ
- ลูปเขียนเอง/ประวัติถูกลบ เริ่มจากสรุปได้โดยไม่แสดงแชทที่แต่งขึ้น
